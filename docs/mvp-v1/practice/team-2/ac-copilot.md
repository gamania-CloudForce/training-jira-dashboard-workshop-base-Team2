# Acceptance Criteria for Team 2 — 價值判斷相關 User Stories

> 針對「缺乏價值判斷，容易浪費時間在低價值功能」的 User Stories，依據 Gherkin 標準格式與驗收標準指引撰寫。

---

## US-001: 價值分數顯示與排序（產品經理）

### AC01: 顯示每個 Issue 的價值分數與明細
```gherkin
場景：產品經理檢視 Jira Dashboard
Given 產品經理已登入並開啟儀表板
When 儀表板載入 Jira Issue 清單
Then 每個 Issue 均顯示價值分數（0–100）
And 顯示分數構成明細（如影響力、觸及面、成本、風險）
```

### AC02: 依價值分數排序與篩選
```gherkin
場景：產品經理依價值分數排序 Issue
Given 儀表板已顯示 Issue 清單
When 產品經理點擊「價值分數排序」或設定篩選條件
Then Issue 清單依分數高低排序或只顯示符合條件的項目
```

### AC03: 查看分數來源與更新時間
```gherkin
場景：展開 Issue 查看分數細節
Given 儀表板已顯示 Issue 清單
When 產品經理點擊某一 Issue 的分數明細
Then 顯示分數來源描述與最近一次分數更新時間
```

## US-002: 價值/投入比與機會成本圖（工程經理）

### AC01: 顯示價值/投入比泡泡圖
```gherkin
場景：工程經理檢視價值/投入比圖表
Given 工程經理已登入並開啟儀表板
When 切換至「價值/投入比」視圖
Then 顯示泡泡圖（X 軸：投入，Y 軸：價值分數，泡泡大小：風險/依賴度）
```

### AC02: 設定投入資料來源
```gherkin
場景：工程經理調整投入資料來源
Given 已顯示價值/投入比圖表
When 工程經理選擇不同投入指標（如 Story Points、Cycle Time）
Then 圖表即時更新並反映新資料來源
```

### AC03: 一鍵產出建議清單
```gherkin
場景：產出高價值/低投入建議清單
Given 已顯示價值/投入比圖表
When 工程經理點擊「建議優先區」或產生建議清單
Then 系統產出高價值/低投入 Issue 清單供參考
```

# SPEC: 功能價值分數顯示（工程開發用）

## 1. 功能說明
在 Jira Dashboard 的功能列表中，為每個功能（Issue）顯示一個「價值分數」，協助團隊聚焦高價值項目，避免資源浪費於低價值功能。

## 2. 流程描述
- 使用者開啟儀表板，系統自動載入所有功能（Issue）資料。
- 前端向後端 API 請求功能清單，後端從 Google Sheets 取得每個功能的 value_score 欄位。
- 前端於每個功能列顯示對應的價值分數。

## 3. 資料來源
- Google Sheets 表格，需有 value_score 欄位（數值型，建議 1-10 分或 0-100 分）。
- 欄位名稱可配置，預設為 "value_score"。

## 4. UI/UX
- 功能列表每列右側顯示「價值分數」欄位。
- 分數以顏色區分（如：高分綠色、中分黃色、低分紅色）。
- 滑鼠懸停分數時，顯示分數計算依據（如有多欄加權，顯示明細）。
- 支援依分數排序與篩選。

## 5. 驗收標準（Gherkin）
```gherkin
場景：儀表板顯示功能價值分數
Given 儀表板已載入所有功能的資料
When 使用者檢視功能列表
Then 每項功能應顯示對應的價值分數（例如：1-10 分）
And 分數應基於 Google Sheets 中的 "value_score" 欄位計算
```

## 6. 例外/邊界情境
- 若 value_score 欄位缺漏，顯示「-」或提示「尚未評分」。
- 若 Google Sheets 連線失敗，顯示錯誤訊息並允許重試。

## 7. 技術備註
- 後端需支援 Google Sheets API 連接與快取。
- 前端需支援分數顏色渲染與排序互動。
